# 10 — Repository root

Parent: `SPEC.md` §3. This level owns the few files that sit next to the
owner's `spec.yaml`, outside `harness/`. None of them is touched by agents
during a round; all survive arbitrary edits to the spec files.

```
<repo root>/
  spec.yaml                owner's (listed in itself)
  SPEC.md                  owner's
  harness/                 -> 20-harness-root.md
  CLAUDE.md                static pointer, three lines
  .gitignore
  .claude/
    settings.json          hooks (committed)
    agents/                generated agent definitions (committed, regenerated by setup)
  .github/workflows/ci.yml CI
```

## CLAUDE.md (static, hand-written, not generated)

Purpose: Claude Code loads `CLAUDE.md` from the project root; `AGENTS.md`
lives under `harness/` and is an owner file. This file routes the driver there.
Content, verbatim intent (three lines, no more):

- You are at the root of the shackles repository. The harness is `harness/`.
- Read `harness/AGENTS.md` first; it is the owner's guide for every agent.
- The driver protocol is `harness/docs/PROCESS.md`; run `python harness/src/run.py doctor` before anything else.

Depends on: nothing. Depended on by: the driver's first turn. A lint test
(`64-tests-lint-drift.md`) asserts the file exists and names `harness/AGENTS.md`
and `harness/docs/PROCESS.md`.

## .gitignore

Ignores exactly the generated, machine-local runtime files:

```
harness/OWNER.log
harness/local.yaml
harness/.worktrees/
harness/.verify/          # scratch output of test verification runs
__pycache__/
.pytest_cache/
```

`.claude/agents/` and `.claude/settings.json` are committed on purpose: the
Agent tool loads definitions at session start, so they must be present in a
fresh clone before `setup` has run `[JC-10]`. `archives/` is committed: it is
the record.

## .claude/settings.json (committed; written by `run.py setup`, checked by `doctor`)

Hooks, and nothing else the harness cares about (other keys the owner has are
preserved verbatim by `setup`, which merges rather than overwrites):

| hook event | command | why |
|---|---|---|
| `UserPromptSubmit` | `python harness/src/run.py hook owner-log` | appends the owner's prompt to `harness/OWNER.log` (`39-src-agents.md`) |
| `SessionStart` | `python harness/src/run.py doctor --quiet` | prints warnings into the session context: drift, stale agent definitions, missing log |

Both commands are relative to the repo root, which is Claude Code's cwd for
hooks. `hooks.py` in `39-src-agents.md` owns the JSON shape; this file is only
its output.

## .claude/agents/ (generated; one file per rung and role)

Written by `run.py setup` from `harness/subAgents.yaml` (`39-src-agents.md`).
File names are `shackles-<rung>.md` (producer, full tools) and
`shackles-<rung>-gate.md` (read-only tools). The driver picks the file `next`
names in its `agent` field. Each file is a Markdown agent definition with
frontmatter `name`, `description`, `model`, `effort`, `tools`, and a one-line
body telling the agent to follow the prompt it is given verbatim. Regeneration
is idempotent; a stale set (roster hash in `local.yaml` differs from the
current `subAgents.yaml` hash) is a doctor warning that says: regenerate and
restart the session, because the Agent tool takes effort only from a
definition loaded at session start.

## .github/workflows/ci.yml

One job, on push and pull request, Python 3.12:

1. `pip install -e harness[dev]` (PyYAML, pytest).
2. `python harness/src/run.py doctor --offline` — must exit 0.
3. `python -m pytest harness/tests -q -m "not live"` — unit, mechanics, lint
   and drift suites; live probes are excluded (they need real agents and keys).

The mechanics suite needs `git` with a user name and email configured; the
workflow sets them. Nothing in CI touches the network except pip.

Depends on: `harness/pyproject.toml` (`20-harness-root.md`). Depended on by:
nothing in the code; it is the safety net for the living paths.
