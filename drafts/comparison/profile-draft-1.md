## 4. Actors and roles

- Owner — speaks in chat; approves, delegates, overrides, answers, abandons; writes nothing during a round.
- Driver — the chat's top-level agent; runs `run.py`; does CHAT-TO-PLAN and checkpoints itself (`SELF`, JC-37); spawns sub-agents with prompt files verbatim, saves their final messages, relays runner messages verbatim; writes only `PLAN.json` and result files; never commits or pushes.
- Producer — fresh sub-agent per attempt in a detached worktree; one step's work; may write declared paths, its artifact(s) and the judgment-call files (via `run.py judgment`).
- Gate — fresh read-only sub-agent (`Read, Grep, Glob`, JC-28); PASS/FAIL with findings in its final message; writes nothing.
- Conflict attempt — a producer attempt at LANDING (`LANDING-<n>`), limited to conflicted files, judged mechanically (JC-41).
- Runner — `harness/src/run.py`: state machine, prompts, checks, git, ledger, owner pauses; alone commits, pushes, prices, and decides when the owner is asked.
- Hooks — `UserPromptSubmit` -> `run.py hook owner-log` (appends the prompt to `harness/OWNER.log`); `SessionStart` -> `run.py doctor --quiet`.
- Nested sub-agents — a producer's own, capped by `maxSimultaneousSubAgentsPerRound` and the agent plan (JC-36); reported only as `subAgentsUsed`.
- Stub agent — tests only; scripted driver, producers, gates. Real agent — `tests/live/adapter.py` via the Claude Code CLI at the `systemTestAgent` rung.

## 5. Architecture: the main mechanisms

a. Step table — `steps/table.py` `TABLE: tuple[Step, ...]`: eleven frozen `Step`s (`kind`, `overviewProse`, `gateProse`, `artifacts`, `inputs`, `declaredPaths` rule, `verify` rule, `overridable`, `skipDefault`, `usesShareOf`); code, "assumed fixed". `steps/lint.py` validates `project.yaml` `steps`, prose files, roster and `roundPaths` against it; unknown step or gate-on-without-prose refuses `start`.

b. Lifecycle / state — `engine/advance.py` `advance(state, ctx) -> Decision`, "the one decision function" (ended -> END; paused -> OWNER restated; open attempt -> same action; open questions -> pause; else by step kind). State: `round/state.py` `RoundState` (`schema: 1`) in `archives/rounds/NNNN/STATE.json`, "the runner's only state" (`phase` open/paused/ended; `stepStatus` pending/working/gating/accepted/skipped); transitions pure, `save` the sole writer; every change committed to `round/NNNN` and fence-pushed.

c. Prompts — `prompts/`: namespaces `prose.STEM`, `project.key` (+ `remaining`, `gates`), `round.key`, `plumbing.PROCESS-INSTRUCTIONS|GATE-PROSE`, `agents.SLUG`; `render.py` substitutes recursively (depth 8), unresolved tokens left verbatim and listed; `plumbing.py` generates a ten-section PROCESS-INSTRUCTIONS block; AGENTS.md verbatim at the head (JC-42). Locked prose included by stem, never interpreted; a missing plumbing token is appended with a warning (JC-12); gate prose always shown to producers, prefixed when off (JC-14).

d. Owner channel — `agents/hooks.handle_owner_log` appends `{ts, session, text}` lines to `harness/OWNER.log`; `round/owner_log.refresh` copies new entries into the round's slice from a machine cursor in `local.yaml` (JC-40); `run.py owner <verb> --quote` is verified as a verbatim substring, whitespace-normalized, latest match wins (JC-15); `round/approvals.py` applies the six verbs as pure transitions; "the runner never parses prose".

e. Git — `git/lease.py`: claim = push of the first commit to `refs/heads/round/NNNN` expecting empty (CAS, one retry with the next id); fence = `push --force-with-lease` after every commit; loss pauses `LEASE`. `git/worktrees.py`: detached `harness/.worktrees/<round>-<attempt>` worktrees plus a persistent runner worktree on the branch (JC-39). `git/landing.py`: merge `main` into the round branch; a conflict is committed as the auto-merged tree with markers and becomes one mechanically judged attempt; `push_to_main` with lease within `syncAttempts`. `git/sync.py`: bounded post-landing merge, never force; folder-only for abandoned rounds (JC-22).

f. Results / verdicts / findings — `round/results.py` extracts the last JSON object, bare or fenced (JC-17), validates per role; contract problems -> mechanical retry. `round/findings.from_gate_result`: rulings first (upheld twice = `settled`), repeats of withdrawn dropped by `repeats` id or normalized quote (JC-18), the verdict wins over blocking flags, PASS resolves open priors; written to `FINDINGS/<producer attempt>.json`. FAIL counts toward `maxTurnsPerGate`, then pause `LIMIT`; `forOwner` findings become `ownerItems`.

g. Money — `ledger/tokens.py` `ceil(bytes / tokenBytes)`; `pricing.py` living file price (base + per-token to cap + over-cap), carry-forward flat rate (JC-20), `testBaseCost` delta, archive costs (plan, spec incl. `SPEC.md` JC-21, postmortem `## Summary`); `living.py` net charge between `mainBefore` and the round head, rename-aware; `agent_costs.py` usage from `--tokens` split by `estOutputFraction`, else a size estimate (JC-23), at rung prices + `spawnCost`; `driverUsdPerStep` once per step (JC-24). Ledger inside `STATE.json` (JC-38), `LEDGER.md` for eyes; booked once at CLEANUP. Hard stops: `round_spend > hardStopBudgetMultiple * quote` (projected living added before landing) and per attempt `cost > hardStopBudgetMultipleIndividual * share` (JC-45). `project.remaining = budget - sum of every round's ledger.total`; `lostValuePerHour` shown, never booked (JC-25).

h. Checks — `checks/mechanical.py` classifies the worktree diff by the step's path rule; strays reverted and noted, never fail; spec files and frozen artifacts are always strays; judgment files append-only. `verify.py` runs `verifyCommand`/`collectCommand` under `verifyTimeoutSeconds`, parses the pytest summary, logs to `.verify/`; timeouts pause `VERIFY` after `maxRoundAttempts` retries. `suite_moves.py` moves whole archived files to `tests-archive/` per `SUITE.json`. COLLECT after SPEC-TO-TESTS; PASS after IMPLEMENTATION, TESTS-TO-SUITE, LANDING, CLEANUP (JC-43).

i. Doctor / lint / index — `commands/doctor.py`: settings + `steps/lint`, drift with diff, owner-log presence, hook/agent staleness, offline render of every prompt with a synthetic round, defaulted keys, commented placeholders, unknown keys, git identity, stale worktrees, open round; `--offline`, `--quiet`, `--fix`. `steps/lint.py` -> `LintReport(errors, warnings, notes)`. `INDEX.md` hand-maintained, lint-checked; not generated.

j. Robustness — SPEC.md §8: prose never parsed; files by name, tokens by namespace, unknown tokens named not guessed; numbers by key with code defaults named by doctor, unknown keys refuse `start`; step table in code validated against `project.yaml`; any spec edit fails `tests/drift/test_spec_files_guard.py` with a diff and refuses `start` until `accept-spec`; mechanics tests use a generated one-line-per-file spec.

## 10. Notable or unusual decisions

- The harness develops itself: `harness/src`, `docs`, `tests` are the living project and the runner (JC-34, high).
- The driver is the chat's top-level agent and performs CHAT-TO-PLAN and checkpoints via `SELF`; only producers and gates are sub-agents (JC-37).
- `STATE.json` is the runner's only state and holds the round ledger; `project.remaining` sums every round's `STATE.json` (JC-38).
- Git is the only lock: CAS push claims the branch, every commit is fence-pushed, a lost lease pauses; runner worktree plus per-attempt worktrees under `harness/.worktrees/` (JC-39).
- Ten defaulted keys with code defaults, each named by doctor (JC-03).
- Owner words arrive via a `UserPromptSubmit` hook; quotes verified as normalized substrings; the round slice starts at a machine cursor (JC-15, JC-40).
- Mechanical checks never fail an attempt: strays are reverted and noted; only contract problems and failing verification re-spawn.
- Final message = last JSON object, bare or fenced (JC-17); findings rules applied by the runner, not asked of the gate (JC-49).
- COMMON-STEP-END inline by default, optional `follow-up` mode via a `phase: step-end` SPAWN (JC-13, JC-31).
- Landing conflict committed as git's auto-merged tree with markers, resolved by one producer attempt judged mechanically, no gate (JC-41).
- Abandoned round lands only its folder, branch kept (JC-22); `maxRoundAttempts` bounds both resumes and mechanical retries (JC-19, JC-27); attempts strictly serial (JC-36).
- `.claude/agents/` and hooks committed and regenerated by `setup` (JC-10); `accept-spec` refuses mid-round (JC-29); live probes via the Claude Code CLI, excluded from CI (JC-33, JC-50).

## 11. Judgment calls

Total: 50 (JC-01..JC-50) in `JUDGMENT-CALLS.md`. 17 entries (JC-12, 15, 16, 27, 30, 31, 36, 37, 39, 40, 41, 43, 45, 46, 47, 49, 50) omit the "why not confident" element the log's own format requires.

Classification scheme, verbatim:

> Two axes on every call.
>
> **Basis** (what the call rests on):
> - `DEFINED` — decidable from the spec files' text alone; I chose one reading of words that are there.
> - `UNDEFINED` — the spec files are silent or conflict; I supplied a rule.
>
> **Kind** (what the call is about):
> - `reading` — interpreting an owner sentence.
> - `mechanism` — how something is done (a platform or git or file mechanic).
> - `default` — a number, name or value the owner never gave.
> - `scope` — what to include or leave out.
>
> **Risk**: `low` (easy to change later, local), `medium` (touches several components or prompts), `high` (changes what the owner sees or pays).
>
> Format per entry: id, the choice, what I chose, alternatives, why not confident, classification, spec sections affected.

Tallies: DEFINED 28 / UNDEFINED 22; mechanism 20, reading 15, scope 8, default 7; low 26, medium 22, high 2 (JC-08, JC-34).

By theme (analyst's grouping):
- Platform / tooling facts (6): JC-10, 13, 28, 33, 35, 42.
