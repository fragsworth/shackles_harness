Five Shackles Drafts

02 · consensus

Where all five agree

Independently, every drafter landed on the same skeleton. Anything below can be treated as settled by the owner's files rather than by any one drafter's taste.

The cast

  • Four roles: an owner in chat, a driver (the top-level chat agent), a runner (harness/src/run.py, plain Python, never talks to a model), and fresh producer and gate sub-agents, one per attempt.
  • The driver performs CHAT-TO-PLAN itself, spawns each sub-agent with the prompt file verbatim, saves the final message unchanged, then calls record.
  • Only the runner commits, pushes, bills, or produces owner-facing text. It never parses prose; it verifies verbatim quotes.
  • Gates are read-only through the tools list (Read, Grep, Glob) and answer PASS or FAIL in their final message.

Stack

  • Python, the standard library plus PyYAML, pytest for tests. No build step: python src/run.py … runs as-is.
  • A GitHub Actions workflow running doctor then the non-live suite. Live probes never run in CI.
  • No draft specifies lint, formatter, or type-checker tooling. All five are silent.
  • Agent definitions generated per rung with model and effort front matter, plus a read-only gate twin; committed, with a staleness check.

Steps and state

  • The eleven-step table is code: a frozen dataclass table linted against project.yaml: steps and the prose directory. Unknown steps, keys, or prose files refuse start.
  • STATE.json in the round folder is the runner's only state; HISTORY.md is append-only and never read back.
  • A round is claimed by a compare-and-swap push of its branch (force-with-lease expecting an absent ref). Every state change is committed and lease-pushed: the fence.
  • Delegation skips only checkpoints. NEEDS-OWNER, BLOCKED, and every limit still pause the round.

Landing

  • A textual conflict becomes one agent attempt restricted to the conflicted files, judged mechanically against git's auto-merged tree.
  • POSTMORTEM and CLEANUP commit after landing and reach main through a bounded sync.
  • The round folder under archives/rounds/NNNN/ is the permanent record; four drafts also land it for abandoned rounds.
  • Remote round branches are kept, never force-pushed over.

Prompts

  • One {{ ns.KEY }} engine over five namespaces: prose, project, round, agents (AGENTS.md ## sections by normalised heading), plumbing.
  • Prose includes resolve recursively with a cycle guard; prose is rendered verbatim, never interpreted for behaviour.
  • PROCESS-INSTRUCTIONS and GATE-PROSE are generated mechanically with no judgment language; COMMON-STEP-END is the prompt's tail.
  • doctor renders every prompt offline against a synthetic round and names unresolved tokens, unknown steps, and defaulted keys.

Owner channel

  • A UserPromptSubmit hook appends every owner prompt to a gitignored OWNER.log (JSON lines). start refuses without it.
  • The driver classifies the owner's words; the runner verifies the quote as a whitespace-normalised substring of the log.
  • The round's slice of the log is copied into the round folder and committed.

Findings and checks

  • The verdict wins and blocking flags follow it; upheld twice is settled; a repeat of a withdrawn finding is dropped by normalised quote with a note.
  • A producer must resolve (fixed or disputed) every finding it was handed, or the attempt is rejected mechanically.
  • Mechanical checks run at record on the attempt's uncommitted diff. Strays outside the declared paths are reverted and noted, never a failure; spec files are always strays.
  • Verification runs the suite under verifyTimeoutSeconds; SPEC-TO-TESTS is checked by collect-only; archived tests move to tests-archive/.

Money

  • One token estimate everywhere: ceil(bytes / tokenBytes).
  • Attempts bill measured usage when the driver reports it, else an estimate from prompt size and estOutputFraction; driverUsdPerStep once per step.
  • The living charge is booked once at CLEANUP on the net diff from main-before-landing to the final tree, with the cap, base cost, and testBaseCost per test function.
  • Archive charges for PLAN, SPEC, and the POSTMORTEM Summary; two hard stops (round multiple, projected before landing; individual per attempt); lostValuePerHour shown, never booked; ledger kept inside STATE.json.

Spec guard and tests

  • A hashed baseline of the spec files; one drift test that fails with a diff; start refuses on drift; accept-spec re-baselines.
  • Mechanics tests run on a generated one-line-per-file spec and never read the real prose, so a prose rewrite fails only the drift test.
  • A stub agent with scripted behaviours drives every runner path in-process; git is real, against a bare local remote.
  • Live probes plant a defect and assert on structure (verdict, quoted text), never on wording. Opt-in only.
  • Docs always include PROCESS.md plus the carry-forward TODO.md and CLARIFICATIONS.md, and a test that keeps docs consistent with code.

05 · against the brief

Where each draft falls short

The brief asked for signatures with typed parameters, returns, purpose and errors; for test cases with their assertions; and for no line-by-line implementation. These are the analysts' concrete findings, one draft at a time, followed by what all five have in common.

D1
  • Parameters are often untyped (s, ctx, state, now); errors are named for only some functions.
  • The optional follow-up step-end mode is never wired into the engine; how a checkpoint gets recorded is unspecified.
  • The hook "prints nothing to stdout", contradicting the one-JSON-object rule; status has no output shape.
  • No unit tests for config/local, engine/attempts, landing_step, booking, or the command modules.
  • Drifts into exact git argv, regexes, and depth constants; 17 of 50 calls lack a rationale.
D2
  • State's body is elided and the StepState it returns is never defined; the control.KINDS strings are never listed.
  • The seven-layer rule is contradicted by its own dependency lists (plumbing → results, render → tokens, doctor → gitops, landing → verify, ledger and limits; results and findings import each other).
  • A schemas module is cited that the draft says does not exist; a step-table row and two comments keep unresolved "?" asides.
  • Living charge, findings reconciliation, landing, next and record are spelled out step by step.
D3
  • The command handlers are listed generically; state.py gives 18 sub-dataclasses by name only.
  • SPEC.md calls paths a leaf while its section depends on config; two return types contradict their prose; doctor --show and --debug are missing from the CLI table.
  • Probe test files are unnamed; three unit-test pairs are listed jointly; authorial asides remain in the text.
  • Prescribes exact git flags, source-surgery rules for archiving test functions, and per-extension index extraction rules.
D4
  • About fifteen helper dataclasses are named without fields (CheckpointView, PauseView, the *Info and *Outcome types, Claim, Change, Slot, InvokeRequest).
  • The nine plumbing templates are given as required sections, not content; all seven docs are outlines.
  • Naming inconsistencies: test_agent_defs versus test_agentdefs, test_doctor versus test_cmd_doctor.
  • Most of the 488 named cases carry no explicit assertion; the 13-item record sequence, exact git invocations and a 90-day price-date constant read as implementation.
D5
  • Parameters untyped in places (cfg, roster, now); nested dataclasses are defined as "mirroring S1"; __init__.py is never mentioned.
  • The stated dependency direction is contradicted by the component files (08 → 05, 09 → 07 and 08, 10 and 11 call each other).
  • check_attempt is declared with three arguments and called with two.
  • Literal file contents, git flags, regexes and magic numbers are fixed in prose.
All
  • No draft specifies lint, formatting, or type-checking tooling.
  • Test assertions are mostly implied by the case name rather than stated.
  • Every draft claims that no file is load-bearing, and every analyst found at least one dependency that breaks the draft's own layering rule.
  • Every draft drifts into exact git invocations, which the brief excluded.

06 · the decisions underneath

What the differences are really asking

Most of the divergence matrix collapses into fourteen choices the owner's files leave open. Each is listed with the camps the drafts fell into; none is settled here.

  1. Where the Claude Code surface lives..claude/, README and CLAUDE.md at the repo root (D1, D2) or under harness/ (D3, D4, D5).
  2. The worktree model.One worktree per round (D2, D3, D4, D5) or one per attempt (D1); nested under harness/ or at the repo root.
  3. What the drift guard stores.Hashes only (D1, D4) or hashes plus full copies so the failing test can print a diff (D2, D3, D5); and whether local.yaml is committed (D3 alone).
  4. The CLI's face.JSON-first with a human flag (D1, D2, D4) or human-first with a JSON flag (D3, D5), and one exit-code table out of five.
  5. The owner's decision vocabulary.Six verbs (D1), seven (D5), nine (D2, D4), or flags on record and resume (D3); plan answers in PLAN.json (D1, D2, D3) or in STATE (D4, D5).
  6. The engine's shape.One sequencer module (D2), one decision function with helpers (D1), a command package (D4), or the engine split by verb (D3, D5).
  7. spawnCost.A floor under the attempt cost (D4, D5) or an addition to it (D1, D3).
  8. How many keys the code may default.Two (D4) up to ten (D1). All five agree testPaths must be one and that unknown keys refuse start.
  9. Self-hosting activation.Fast-forward the main checkout mid-round so the landed runner finishes the round (D3), hold until the next round (D5), or route only judgment and spawn through the driver checkout (D4).
  10. A red suite at record.A separate refused counter (D2), a gate turn (D3, D4, D5), or a round attempt (D1).
  11. Test archiving granularity.Whole files (D1, D4, D5) or individual functions cut out by ast (D2, D3).
  12. INDEX.md.Generated (D2, D3, D5) or hand-maintained and checked (D1, D4).
  13. Hooks.The prompt hook only (D3, D4) or prompt plus SessionStart (D1, D2, D5).
  14. Docs beyond PROCESS, TODO and CLARIFICATIONS.From one extra file (D5) to six (D3).
