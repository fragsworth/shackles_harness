# 00 — Repository layout, tooling and non-code files

Parent: [`../SPEC.md`](../SPEC.md). This file describes everything in the repository that
is *not* a Python module under `harness/src/`, a doc under `harness/docs/`, or a test
under `harness/tests/`. Those three trees have their own files (01–07, 09, 10).

## 0.1 The two roots

| Name | What it is | How code finds it |
|---|---|---|
| **REPO_ROOT** | the git top level | `git rev-parse --show-toplevel` |
| **HARNESS_ROOT** | the directory holding `project.yaml` (today `REPO_ROOT/harness/`) | walk up from `src/run.py`'s own directory until a `project.yaml` is found |

Every relative path in the owner's files (`livingSourcePaths`, `lockedProsePath`,
`archivesPath`, `roundPaths.folder`) is relative to HARNESS_ROOT. Git reports paths
relative to REPO_ROOT; `paths.py` (file 01) converts. Nothing else may assume that
HARNESS_ROOT is exactly `REPO_ROOT/harness/` (JC-01).

The spec index `spec.yaml` is found by looking in HARNESS_ROOT, then each parent up to
and including REPO_ROOT; the first hit wins. Its `files:` entries are relative to the
directory that holds it.

## 0.3 Ownership rules for the tree

- Only the runner writes under `archives/`, `spec-baseline/`, `.claude/agents/`, `INDEX.md`
  and `local.yaml`. Producers write only inside their attempt's declared paths and the
  round folder (file 04, worktree).
- No file listed by `spec.yaml` is ever written by any code in this repository. The one
  exception is *reading* them to snapshot into `spec-baseline/`.
- Nothing under `harness/` outside `src/`, `docs/`, `tests/` is a living path unless the
  owner changes `livingSourcePaths`. Generated files therefore live outside those three
  trees so their tokens are never charged (JC-02).

## 0.5 `.claude/settings.json`

Two hooks, both calling the runner, both cheap and side-effect-bounded:

| Event | Command | Effect |
|---|---|---|
| `UserPromptSubmit` | `python3 "$CLAUDE_PROJECT_DIR/harness/src/run.py" hook prompt` | reads the hook JSON on stdin, appends one JSON line `{ts, session, text}` to `harness/OWNER.log`; never blocks the prompt; exit 0 even on failure (writes the failure to stderr) |
| `SessionStart` | `python3 "$CLAUDE_PROJECT_DIR/harness/src/run.py" hook session-start` | prints to stdout (which Claude Code shows the driver) whether `.claude/agents/` matches `subAgents.yaml` and whether the spec baseline is clean; regenerates nothing (JC-06) |

The hook commands are the only place the repository assumes `$CLAUDE_PROJECT_DIR` is
REPO_ROOT. `doctor` checks that the settings file contains exactly these two hooks with
these commands (string match after whitespace normalisation) and reports otherwise.

No permissions block is required; the driver gets its own permissions from the user.

## 0.6 `harness/README.md` (hand-written, not charged)

Sections, each a few lines: what the harness is (one paragraph, quoting nothing from the
owner files so it never drifts); requirements (Python ≥ 3.11, git ≥ 2.38, a configured
remote); install (`pip install -r requirements.txt`); first-time setup
(`python3 src/run.py doctor`, `python3 src/run.py agents`, restart the Claude Code session,
`python3 src/run.py accept-spec --quote ...` if the baseline is missing); the driver's
loop verbatim from `docs/PROCESS.md` §Driver loop (kept in sync by a test, file 10
`test_docs.py`); how to run tests (`pytest`, `SHACKLES_LIVE=1 pytest -m live` for probes).

## 0.7 `.github/workflows/ci.yml`

One job, Ubuntu, Python 3.11 and 3.12 matrix (JC-05):
1. `pip install -r harness/requirements.txt`
2. `python3 harness/src/run.py doctor --offline --json` (must exit 0)
3. `pytest harness/tests -m "not live"` (must exit 0)

The drift test is part of step 3, so CI is red whenever a spec file changes until the
change is accepted — exactly what the owner asked for. Live probes never run in CI.

## 0.8 `harness/pyproject.toml` and `requirements.txt`

`pyproject.toml` carries only tool configuration:
- `[tool.pytest.ini_options]`: `testpaths = ["tests"]`, `markers = ["live: spawns a real agent; opt in with SHACKLES_LIVE=1"]`, `addopts = "-p no:cacheprovider"`, `pythonpath = ["src"]`.
- No `[build-system]`, no packaging: `src/` is used in place; `run.py` inserts its own directory on `sys.path` so sibling modules import flat (`import config`, `import gitops`, ...).

`requirements.txt`: `pyyaml>=6`, `pytest>=8`. Nothing else at runtime; the runner is
standard library plus PyYAML.

## 0.9 `harness/archives/README.md` and `archives/rounds/`

`archives/README.md`: three lines — the record; one folder per round; layout from
`project.yaml roundPaths`; left alone once a round is complete. `archives/rounds/.gitkeep`
so the folder exists on a fresh clone. The per-round layout is specified in file 08.

## 0.10 `harness/spec-baseline/`

The accepted snapshot of every file `spec.yaml` lists, written only by `run.py accept-spec`
(file 01, speclock). Storing copies rather than only hashes is what lets the drift test
print a unified diff (JC-04). It lives outside the living paths so it is never charged.
