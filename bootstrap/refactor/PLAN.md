# Build plan: the harness after the owner's files

What the harness does once the code matches the files spec.yaml lists, as of the owner's commits of 2026-09-14; HANDOFF.md names the last one. Behaviour only; the builder chooses the module layout under one rule: code names follow the owner's keys. Bracketed numbers point at JUDGMENT-CALLS.md beside this file. Written by the coordinating session on 2026-09-14 and reviewed by the owner in chat.

**Owner files.** spec.yaml's list is expanded, globs included, and the baseline records the expansion, so a prose file added or removed is drift. subAgents.yaml is guarded like project.yaml [D1]. Inside a round, an agent's change to any guarded file is reverted at record with a finding; no provisional acceptance, no spec-edit checkpoint [D2]. Every key in the two YAML files is read by something, or start refuses; a key the code offers but the file lacks takes its default, and doctor names it [D3]. local.yaml holds only what the runner discovers and writes itself, such as the claude path [D4]. `vision` replaces the old `shackles` default [D32].

**Steps.** The table in code mirrors the `steps` block: same names, same order, one gate per producer, checkpoints as rows of their own; a mismatch refuses to start [D5]. CHECKPOINT-1 pauses on the spec and CHECKPOINT-2 on the diff before landing; delegation skips exactly these two; the pause message carries the CHECKPOINT-OVERVIEW text so the driver knows what to do [D6]. LANDING is the runner alone: merge, verify, suite, push, tag [D7]. POSTMORTEM and then CLEANUP run after landing as agent steps without gates; cleanup may touch the living paths and the round folder, verify and the suite must stay green, and its commits reach main by the bounded sync; then the round ends and every agent stops [D8, U10]. The CHAT-TO-PLAN flag is inert until a gate prose exists for it; the owner's approval word is always required to start [D9]. The gate list agents see is derived from the block [D10]. Upstream stays off: a wrong earlier artifact is a question for the owner [D31, U1].

**Money.** Every price is per token, a token being bytes over tokenBytes, rounded up [D11]. Agent runs are booked at what they cost; a run with no measurement books the spawn floor with a flag [U2]. The driver overhead is booked per recorded attempt and once at start for the plan, as the estimate of a real cost, and enters the retry cost shown to gates; the planning share enters the quote only [D18]. lostValuePerHour is rendered into prompts and nothing more; the runner keeps no time cost and no owner cost [D17]. At cleanup the runner books, once: the living charge on main-before-landing versus the tree cleanup leaves, renames free, test base cost per net new test function, archived tests free [D12]; the tokens of the plan, the spec and the postmortem Summary, never refunded; and the carry-forward deltas at their special rate [D13]. The quote includes the planner's estimate of the living charge, and the work and gate fractions split the rest [D14]. The hard stop compares spend plus the projected living charge with multiple times quote before every agent run and before landing; approving a hard stop needs a new multiple from the owner, which re-arms it; bookings after landing never pause the round [D15]. The individual multiple caps one run where the runner can cap it, and a recorded run over it pauses the round [D16]. An off gate's share is simply unspent [D19]. Refactor overhead and default shares are printed, not enforced; the two fractions must sum to one [D20].

**Limits.** Rejections of one producer, by its gate or by the mechanical checks, count toward maxTurnsPerGate; re-entries count toward maxRoundAttempts; reaching either pauses the round [D21, U11]. Wall clock is measured in both modes, stamped when the action prints and read at record, and a breach pauses the round; turns can be capped only where the runner launches the agent itself, so maxTurnsPerRun is a headless-only limit and doctor says so [D22]. A plan may not name a rung above maxAgent; defaultAgent is the default for work and systemTestAgent the rung probes use [D23].

**Talking to the owner.** A question always pauses the round: the gate no longer rules on it, nothing settles silently, and the producer stops instead of building on an assumption. The owner's answer returns as a finding and the producer runs again. At a question the runner accepts only an answer, and the driver turns whatever the owner said into one [D24]. Start refuses without an owner log, and a quote the log does not contain is refused [D25, U3]. Every pause and the final report list what was flagged for the owner: deferred findings, non-blocking findings, suite items raised with the owner, sibling overlaps [D26].

**Findings and judgment calls.** A finding omitted from a producer's resolutions stays open and the attempt is rejected; a re-raised withdrawn finding is dropped with a note; upheld twice is settled [D27]. One recorder for judgment calls: a runner subcommand appends one line tagged with step and attempt, the process block names it, gates keep reporting in their final message, and the runner counts the files [D28, U8]. The recorder answers each call with the big picture, the vision and the judgment-call definitions, so the reminder arrives at the moment of the call [D35]. COMMON-STEP-END is delivered as a second turn to the same sub-agent when its work is done, and the message after it is what gets recorded; headless runs resume the session for it [D29, U9]. `{{ agents.X }}` renders the matching AGENTS.md section [D30].

**Retired.** The gates key, checkpointsAfter, maxFailuresBeforeStop, the owner bucket, the word prices, the plan-share booking at start, the gate's question ruling, the silent settle, the assumption field, E1 and the spec-edit checkpoint, UPSTREAM in the contract, and --unverified [U4]. Kept, because the owner's files name them and the code already matches: the CAS claim, worktrees, the landing merge attempt, sync_main, the mechanical checks, the render engine, the fixture spec and the stub [U5, U6].

**Sequence.** Six slices in dependency order, each leaving doctor clean and the suite green: owner files and config; step table and checkpoints; ledger; owner interaction and findings; judgment-call tooling and the step-end turn; docs regenerated and the stub extended [D33, U7]. One builder in a worktree; a reviewer against the owner's files after the step table and at the end; then a sandbox round with real agents and checkpoints on, from a session started inside the sandbox repo so the hook logs the owner's words. The owner's part: fix the spelling of subAgents.yaml in spec.yaml, then `spec accept`, commit, push, promote main.

**Settled with the owner on 2026-09-14, read against the vision.** The driver overhead is booked [D18]; wall clock is measured at record in both modes and turns are headless-only [D22]; mechanical rejections count toward maxTurnsPerGate [D21]; the readings D9, D14 and U2 stand as written.
